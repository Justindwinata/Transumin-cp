# Database Contract V1

**Status:** CANONICAL CONTRACT — PHASE 1 TRANSIT FOUNDATION IMPLEMENTED

## Global rules

Internal PKs are UUID. External IDs are scoped by source and dataset version. Event timestamps use `timestamptz`; GTFS arrival/departure use non-negative service-day seconds and may exceed 86400. Geometry uses a declared SRID and GiST indexes. Availability and evidence are separate constrained values. Required FKs are non-null unless the row legitimately precedes its parent association. Parent deletion defaults to `RESTRICT`; immutable research/run lineage is never cascaded away. Soft lifecycle status is preferred for referenced definitions.

## Scenario effective-state rule

`effective_state(entity, run) = network_snapshot.mobility_state(entity) overlaid by simulation_state_override(entity, run)`. Missing overrides preserve base state. Execution cannot update base rows. Action types are `SET_AVAILABILITY`, `BLOCK_ENTITY`, `DEGRADE_ENTITY`, and `RESTORE_ENTITY`; all produce `SIMULATED` provenance.

## Lineage invariants

Impact traces to event + snapshot + rule/engine version; simulation to scenario + run + snapshot + config/engine; recovery to immutable selected journey + progress revision + current impact/state transition + shared snapshot/anchor/time + method fingerprints; operator recovery to route + run + assumptions + algorithm. Dataset-version columns need not be duplicated when an immutable parent path resolves them, but every result must be reconstructable with FK-backed lineage.

## Phase 1B real-data reconciliation

Migration `202609290001_gtfs_source_fidelity` is the smallest schema correction justified by the verified TransJakarta GTFS snapshot. The feed contains 163 route/direction combinations with multiple stop patterns, so segment uniqueness is trip-scoped. Its 14 transfers connect GTFS stations rather than platform stops, so transfer endpoints support an explicit stop-or-station XOR. Route description and presentation metadata are stored in typed columns to prevent source-fidelity loss. The retrieved feed has `calendar.txt` and no `calendar_dates.txt`; therefore no service-exception table is authorized in this phase. A future feed containing service exceptions must add that model before ingestion rather than dropping exception rows.

## Phase 1C real-data hardening

Migration `202609290002_phase1_transit_hardening` reconciles two facts from the same immutable feed. First, all 700 trip templates are referenced by 753 `frequencies.txt` rows, so frequency windows are canonical schedule semantics. Second, 25,727 trip-scoped traversals reduce to 17,727 stable route/direction/endpoint edges; state identity therefore moves to the logical segment while `trip_segment_traversal` preserves trip sequence and exact geometry. ADR-007 records this change. The rebuild is pipeline-versioned and transactionally replaces only the same dataset version.

## Phase 1D operational-data boundary

Phase 1D authorizes no operational persistence migration. It freezes in-memory canonical observation, incident-candidate, provenance, freshness, authority, and conflict contracts while Phase 2B retains ownership of Mobility Twin state/history storage. The future schema must preserve every accepted observation and resolution lineage rather than overwriting source evidence, must store explicit expiry, and must keep operational state separate from evidence type. The operator-console domain contract exists without a public endpoint until authentication, authorization, audit retention, and idempotency are specified.

## Phase 2A spatial foundation

Migration `202609300001_spatial_pedestrian_foundation` implements the bounded OSM foundation. `spatial.network_node` and `spatial.walking_edge` are version-scoped, PostGIS SRID 4326, and preserve source way/tag lineage; walking-edge endpoint columns are composite FKs to the same dataset version. `spatial.transit_endpoint_resolution` makes resolved, fallback, and unresolved station/stop snaps explicit. `spatial.rail_topology_station` and `spatial.rail_topology_edge` are corroborated `TOPOLOGY_ONLY` records and never imply operator schedules or live status.

`meta.source_entity_reference` and `meta.entity_alias` scope operational identity to source, operator, and dataset version. Alias keys are intentionally non-unique across canonical entities so ambiguity remains queryable. `spatial.interchange_candidate` stores the 1 km geodesic baseline separately from actual pedestrian network distance and path status. These records are derived from the tracked OSM and Phase-1 transit manifests and are not Mobility Twin state/history.

## Phase 2B operational Mobility Twin

Migration `202610010001_hybrid_mobility_twin` implements append-only observations, a transactional current-state read model, transition history, and immutable sparse network snapshots. Projection considers source authority, observation and receipt cutoff, expiry, and canonical evidence validation. No fresh evidence projects `UNKNOWN`; missing snapshot membership has the same meaning. Environmental or forecast indicators cannot independently persist an `UNAVAILABLE` transport condition.

The current state can be rebuilt from immutable observations, while history records only meaningful condition changes. Snapshot content hashes canonicalize configuration and sorted states, bind the Phase-1 transit and Phase-2A spatial dataset versions, and exclude ADR-003 scenario overrides. Finalization triggers prevent metadata or membership mutation.

## Phase 3 disruption and scenario intelligence

Migrations `202610010002_live_operational_gateway` and `202610010003_disruption_and_simulation_intelligence` add source-health checks, canonical disruption events, structured entity impacts, impact analyses, scenario definitions/actions, simulation runs, run-specific state overrides, and structured impact results. `disruption.entity_impact` enforces that `DIRECT_EXPOSURE` has no resulting operational condition: geometry intersection is exposure, not closure.

Runtime table names are `simulation.scenario`, `simulation.scenario_action`, `simulation.run`, `simulation.state_override`, and `simulation.impact_result`. Every override is constrained to `SIMULATED`; the immutable `twin.network_snapshot` and its membership are never updated by a run. Run idempotency is unique within scenario scope, while application validation rejects reuse of a key with a different canonical request hash. `UNKNOWN` remains traversable in the connectivity baseline; only explicit `UNAVAILABLE` edges are blocked.
