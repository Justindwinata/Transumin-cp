Stabilisasi alur penumpang TRANSUM-IN NEXUS, 19 Oktober 2026

Milestone ini menindaklanjuti instruksi Product Owner untuk FR-001, FR-002, FR-006 dan FR-009: lokasi perangkat, empat preferensi, kombinasi transportasi, perjalanan aktif, recovery, dan pilihan lanjutan ke penyedia eksternal. Pekerjaan berada di checkout TRANSUM-IN-NEXUS-TAKEOVER pada branch codex/deployment-readiness, dengan perubahan audit sebelumnya tetap dipertahankan. Tidak ada migration, pengubahan database produk, distribusi graph, atau public deployment.

Pembacaan lokasi memakai browser Geolocation watchPosition setelah persetujuan pengguna. Timeout/position-unavailable tidak lagi menghentikan watch secara permanen: callback fix berikutnya dapat memulihkan status. Penolakan izin menghentikan watch dan menghapus posisi yang tersimpan di memori. Kesalahan sinkron browser ditangani sebagai state error, dan tombol mencoba ulang tersedia pada pencarian maupun perjalanan aktif. Pengguna dapat berhenti berbagi sebelum memulai perjalanan. Watch berhenti saat perjalanan selesai serta saat tab disembunyikan, lalu dapat berlanjut saat tab kembali terlihat selama pengguna masih memilih berbagi.

Koordinat dan akurasi selalu berasal dari fix yang sama. Filter sebelumnya dapat mempertahankan koordinat coarse lama sambil mengganti akurasinya dengan akurasi fix baru, sehingga memberikan kesan presisi yang tidak didukung. Filter tersebut dihapus dari penyimpanan posisi mentah; penanganan jitter navigasi tetap berada di modul navigasi. Fix harus segar, tidak berasal dari masa depan, akurasinya memadai, dan state aktif sebelum dipakai untuk pencarian current-location maupun penyalinan pickup. Timeout, izin dicabut, stopped, requesting dan stale tidak dapat memanfaatkan posisi lama sebagai posisi yang siap digunakan.

Ambang navigasi tetap 30 meter dan freshness tetap 30 detik. Fix 31–250 meter dapat ditampilkan sebagai konteks, tetapi tidak otomatis menjadi dasar navigasi. Pengguna dapat secara eksplisit mengonfirmasinya sebagai pin dan memperbaiki titik di peta. Titik ini tidak dinyatakan sebagai hasil GPS presisi. Geolocation tidak mengirim permintaan planning otomatis. Koordinat baru dikirim ke planner saat pengguna mencari rute; penyalinan ke clipboard juga memerlukan tindakan pengguna. GPS tidak menjadi bukti otomatis boarding, alighting atau selesai.

Pencarian awal sekarang menggunakan tanggal dataset historis yang memang didukung, bukan tanggal sistem yang dapat langsung ditolak oleh service-date guard. Banner tetap menjelaskan snapshot terjadwal 2 Oktober 2026. Perubahan asal, tujuan, koordinat, tanggal atau pin membatalkan pencarian lama dan membersihkan kandidat lama. Pemilihan preferensi memakai input terkini dan bukan koordinat yang tersimpan dari pencarian terdahulu. Tombol skenario juga mengembalikan metode input ke place agar input Current/pin sebelumnya tidak tercampur dengan skenario.

Pilihan Gojek, Grab dan Bluebird tersedia untuk perjalanan aktif tanpa bergantung pada leg navigasi tertentu. Tujuan berasal dari destination perjalanan aktif; pickup hanya berasal dari fix GPS yang masih layak, bukan tebakan dari awal leg atau lokasi kendaraan. Pengguna dapat menyalin tujuan, pickup atau detail perjalanan. Jika clipboard tidak didukung atau diblokir, detail yang diminta ditampilkan sebagai teks yang dapat disalin manual setelah tindakan eksplisit. Tautan hanya menuju homepage HTTPS resmi tanpa query koordinat. Tarif, ETA, ketersediaan, prefill dan booking tidak dinyatakan telah terintegrasi. Penjelasan Geolocation dan layanan resmi ditinjau melalui https://www.w3.org/TR/geolocation/, https://www.grab.com/id/en/transport/ dan https://www.bluebirdgroup.com/; halaman bantuan Gojek yang dicoba tidak memberi bukti kontrak API prefill.

Pengujian browser GPS_STABILITY memakai input SIMULATED secara eksplisit. Pada lebar 390 dan 1280 piksel, pengujian memeriksa timeout lalu pemulihan pada watch yang sama, pencabutan izin, retry, konfirmasi coarse fix sebagai pin, stale clock, exception browser sinkron, stop, tidak ada permintaan planning otomatis dan tidak ada horizontal overflow. Ini menguji software, bukan akurasi sensor fisik, penerimaan izin OS pada perangkat tertentu, atau lokasi di jalan nyata.

Matriks ROUTING_STABILITY mengeksekusi 28 pencarian API/OTP nyata: tujuh pasangan lokasi dengan BALANCED, FASTEST, FEWEST_TRANSFERS dan LEAST_WALKING. Lokasi diselesaikan dari katalog canonical/indeks OSM yang ada. Hasil mencakup WALK, TRANSJAKARTA, MIKROTRANS, KRL, MRT_JAKARTA, LRT_JAKARTA dan LRT_JABODEBEK, termasuk perjalanan yang memakai lebih dari satu moda transit. Tes memeriksa durasi/jarak valid, transfer count, urutan leg, koneksi waktu, urutan preferensi pada kandidat yang dikembalikan, serta kegagalan domain terstruktur untuk titik di luar cakupan. Pengujian tidak membuktikan optimum global atau bahwa setiap pasangan koordinat di seluruh wilayah mempunyai koneksi transit.

HANDOFF menguji pembukaan pilihan resmi tanpa pengiriman lokasi otomatis, penyalinan tujuan, pickup GPS SIMULATED setelah izin, penolakan pickup sesudah stop, dan fallback saat clipboard hilang. COMBINED dan PLACE_NEGATIVE menguji ulang alur penumpang pada 390/1280, termasuk report-unverified, controlled review SIMULATED, real OTP recovery, acceptance, reload, completion serta perjalanan berikutnya. Scope ini mempertahankan bukti terjadwal, teramati dan simulasi secara terpisah.

Satu masalah Docker Desktop berhasil direproduksi: bind-mount scratch gagal start dengan FATAL wrong ownership. Opsi --managed-volume memakai volume Docker baru yang namanya berasal dari UUID invokasi. Mount, label volume/container, server/database identity, runtime grants serta reserve ruang tetap diperiksa. Volume produk tidak diadopsi. Cleanup hanya menyasar volume/container invokasi yang identitasnya cocok dan hanya setelah hasil serta penghapusan database scratch terverifikasi. Percobaan gagal sebelumnya tetap tersimpan; container milik dua percobaan gagal dihentikan setelah verifikasi identitas tanpa menghapus bukti/datanya.

Perintah pnpm passenger:local menyediakan runtime lokal terisolasi. Perintah memerlukan environment database sumber yang disetujui melalui .env atau environment shell; source database hanya dibaca, sedangkan perubahan journey/report berada pada scratch milik invokasi. Runtime memakai production web di HTTPS loopback dan token sesi/service acak setiap invokasi. --serve-local mempertahankan server setelah acceptance, lalu Ctrl+C/SIGTERM menjalankan cleanup yang memeriksa ownership. Data UAT bertahan saat reload selama invokasi hidup, tetapi bukan penyimpanan produksi permanen. HTTPS memakai sertifikat self-signed lokal, sehingga browser/perangkat perlu mempercayainya untuk penggunaan lokasi; ini bukan public TLS. Pembukaan sesi browser baru diperlukan bila cookie prototype dari runtime lokal lain masih tersimpan.

GPS fisik tetap NOT VERIFIED sampai pengguna mencoba perangkat nyata dengan secure context dan izin OS/browser. Tanggal/jadwal saat ini, cakupan jaringan di luar input historis, bukti keselamatan pedestrian, integrasi booking penyedia, dan izin produksi/distribusi rail/graph belum ditutup oleh pekerjaan ini. Aplikasi tidak menjanjikan rute untuk titik yang tidak terhubung ke jaringan. Jika tidak ada koneksi, pengguna memperoleh kegagalan yang jelas dan dapat menggunakan opsi manual penyedia eksternal. Ini merupakan batas data dan integrasi yang nyata, bukan kondisi yang boleh ditutupi dengan rute atau jadwal rekaan.

Verifikasi source menjalankan pnpm check:source: 132 tes API, 82 tes web dan 3 tes script lulus, beserta lint, typecheck, metadata kontrak data, OpenAPI/types, format dan build. Metadata tidak menggantikan verifikasi byte raw dataset privat. Bukti terdapat di .release-evidence/passenger-stability-20261019; source-manifest.json mencatat hash snapshot kerja yang belum di-commit, bukan release produksi.

Pemindaian secret source dan bundle browser lulus (489 source file, 26 client file, failures kosong). Cache privat Turbopack mengandung konfigurasi server; izin direktori/file dibatasi menjadi 700/600. Cache, .env, .next, data dan artefak runtime tidak boleh dimasukkan paket distribusi. Hasil ini bukan klaim bahwa seluruh cache bebas secret.

Pengecekan kesiapan runtime setelah acceptance menemukan HTTP 502: pembuktian backup exact-grants memang menghentikan API/web, tetapi opsi serve-local sebelumnya belum menyalakannya kembali. Lifecycle diperbaiki dengan start ulang API/web setelah backup dan probe HTTPS yang wajib mengembalikan HTTP 200 sebelum LOCAL_PASSENGER_READY. Screenshot handoff mobile juga memperlihatkan tautan terlalu rapat; flex gap dan target sentuh minimum 44px ditambahkan. Invokasi c8ee5d25 tetap menjadi bukti suites sebelum dua perbaikan terakhir tersebut; runtime dan bukti terbaru memakai invokasi terpisah.
