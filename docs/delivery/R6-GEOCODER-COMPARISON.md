# R6 F02 — Perbandingan geocoder alamat Jakarta/Jabodetabek

**Tanggal bukti:** 14 Oktober 2026  
**Status kualitas alamat residensial:** `NOT_VERIFIED` — belum ada uji sampel berizin. Dokumen ini bukan jaminan cakupan.  
**Batas keputusan:** perbandingan saja; tanpa akun berbayar, unduhan data, deployment, atau integrasi. G3 tetap `BLOCKED_BY_AUTHORIZATION` sesuai [permintaan otorisasi G3](./G3-GEOCODING-AUTHORIZATION-REQUEST.md).

## Ringkasan keputusan

**Rekomendasi untuk uji 5–10 alamat:** otorisasi uji terbatas **Geoapify Free** lebih dahulu, hanya bila Product Owner menerima pengiriman kueri alamat ke penyedia/EU dan retensi request yang dinyatakan umumnya paling lama 24 jam. Alasannya: tanpa kartu kredit, 3.000 kredit/hari, hingga 5 request/detik, filter negara/kotak wilayah, autocomplete resmi, dan hasil boleh disimpan dengan atribusi. Ini rekomendasi uji, bukan pilihan produksi.

**Pembanding kedua:** Google Maps Platform, bila billing account dan tinjauan syarat Google sudah tersedia/diizinkan. Geocoding API cocok untuk pencarian alamat setelah submit; kebutuhan saran saat mengetik memakai **Places API (New) Autocomplete**, bukan Geocoding API saja. Google berpotensi menjadi pembanding kualitas kuat, tetapi kualitas lokal tetap `NOT_VERIFIED`, billing wajib, caching umumnya dibatasi, dan tampilan membawa aturan Google Maps.

**Tunda self-hosted Nominatim/Photon/Pelias** untuk F02. Opsi ini memberi kontrol runtime dan tanpa biaya per-request vendor, tetapi butuh sumber data berlisensi, import/update, kapasitas terukur, observability, keamanan, dan operasi. Tidak sebanding dengan uji 5–10 alamat sebelum benchmark host.

**Larangan tetap:** jangan gunakan public `nominatim.openstreetmap.org` untuk autocomplete. Kebijakan resminya melarang autocomplete dan meminta agar data pribadi/rahasia tidak dikirim.

## Fakta ukuran data vs kapasitas yang belum diketahui

Geofabrik menyediakan extract Indonesia OSM PBF sekitar **1,6 GB** pada 14-10-2026, data sampai 13-10-2026. Itu hanya ukuran input terkompresi, **bukan** kebutuhan disk index, RAM, waktu import, atau ruang update Nominatim/Photon/Pelias. Tidak ada angka host Jabodetabek yang dapat dijamin dari ukuran tersebut. Sebelum memilih self-hosted, jalankan import berizin pada host disposable dan catat peak RAM, disk setelah index, durasi, latency p95, ruang update, checksum serta versi sumber. Jangan mengunduh extract dalam milestone perbandingan ini.

## Trial 5–10 alamat yang perlu diotorisasi

1. Product Owner menyediakan 5–10 kasus Jabodetabek yang boleh diproses: campuran nomor rumah, jalan/gang, perumahan, kelurahan/kecamatan, variasi singkatan/ejaan, serta Jakarta dan kota satelit. Gunakan alamat milik penguji atau data publik/nonpersonal yang izin penggunaannya jelas; jangan menyalin alamat warga acak.
2. Catat expected pin/reference secara independen dan sumbernya. Jika ground truth tidak kuat, tandai kasus `AMBIGUOUS`, bukan gagal/lulus paksa.
3. Uji string identik, `language=id`, filter Indonesia, bias/restriction Jabodetabek, jumlah hasil sama. Untuk autocomplete, catat prefix yang sama, debounce, jumlah request, dan apakah pilihan benar muncul; jangan memakai public Nominatim.
4. Nilai per kasus: kandidat benar di top-1/top-3, jarak ke reference, komponen nomor-jalan-kelurahan-kota-kode pos, jenis hasil/interpolasi, latency, empty/error, atribusi, dan estimasi request/cost dari SKU resmi. Label semua keluaran `NOT_VERIFIED` sampai review manusia.
5. Hapus artefak kueri sesuai retention yang disetujui; simpan hanya matriks hasil yang diminimalkan/pseudonim bila diizinkan. Trial tidak mengubah status produksi dan tidak membuktikan coverage seluruh Jakarta/Jabodetabek.

**Gate keputusan sesudah trial:** pilih provider hanya jika kriteria penerimaan, batas biaya bulanan, volume/rate limit, lokasi pemrosesan, retention/deletion, atribusi/caching, credential owner/rotation, dan precise-address egress disetujui tertulis. Jika tidak, pertahankan pin/koordinat/stasiun sebagai fallback aman.

## Kondisi repositori

`.env.example` tidak berisi key geocoder. Hanya placeholder provider lain; kredensial sengaja tidak ada. Jangan menambah key sebelum provider dan owner disetujui. Implementasi kelak harus memakai server-side secret atau restriction yang sesuai provider, bukan nilai rahasia `NEXT_PUBLIC_*`.
