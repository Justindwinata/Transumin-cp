Perbaikan pencarian dengan cookie sesi lama, 19 Oktober 2026

Product Owner melaporkan bahwa Find journeys tidak menghasilkan alternatif dan menampilkan Session is invalid. Lingkup perbaikan adalah FR-001/002 dengan batas kepemilikan FR-014 tetap dipertahankan. Source tetap checkout TRANSUM-IN-NEXUS-TAKEOVER pada codex/deployment-readiness; perubahan audit/stabilitas sebelumnya tidak dihapus. Tidak ada schema migration atau pengubahan database produk.

Penyebab direproduksi pada runtime sebelum perbaikan: POST /api/passenger/journeys/plan dengan cookie usang mengembalikan 403 INVALID_SESSION. Kunci HMAC runtime UAT memang dibuat acak per invokasi, tetapi cookie HttpOnly dari invokasi lama masih dapat tersimpan di browser. Cookie bertahan melampaui invokasi server juga mempunyai batas waktu payload 12 jam. Proxy sebelumnya memperlakukan pencarian baru dan akses perjalanan tersimpan sama-sama sebagai operasi yang harus menolak cookie invalid; pengguna terjebak meskipun hanya ingin mencari rute baru. Ini kesalahan lifecycle sesi aplikasi, bukan kegagalan GPS atau hasil routing kosong.

Pencarian baru kini menjadi batas pembuatan sesi tamu baru: hanya POST journeys/plan dapat mengganti cookie invalid/expired dengan identitas acak server yang berbeda. Identitas yang tercantum pada cookie invalid tidak pernah dipakai sebagai owner. Penjagaan same-origin, secret server minimum, token service, allowlist, HttpOnly, SameSite Strict serta Secure produksi tetap berlaku. Tidak ada retry otomatis pada progress, boarding, alighting, report, recovery acceptance, atau operasi perjalanan yang sudah dimiliki. Cookie invalid pada operasi tersebut tetap ditolak sebelum upstream dipanggil. Perjalanan lama tidak diadopsi oleh sesi baru.

Pencarian katalog transit dan planning-health merupakan pembacaan publik yang tidak menentukan kepemilikan perjalanan. Keduanya dapat bekerja dengan cookie usang, tanpa mengganti cookie browser. Permintaan paralel saat startup tidak lagi berlomba menulis cookie dengan dua owner berbeda. Cookie valid tetap mempertahankan owner yang sama pada pencarian dan perpindahan preferensi. Input titik asal/tujuan dan pilihan pengguna tidak dibuang untuk memperbaiki sesi; pengguna tidak perlu menghapus seluruh data browser atau memakai Incognito sebagai solusi bug ini.

Tes g1-session-security.test.mjs memanggil handler Next nyata dengan upstream terkontrol untuk memeriksa HMAC valid/invalid, expiry, signature yang diubah, owner spoofing, kunci lama, penolakan origin, konfigurasi secret hilang, serta public lookup tanpa pergantian owner. Suite ini sekarang menjadi bagian dari pnpm --filter @transum-in/web test. Seluruh 95 tes web lulus, begitu pula typecheck dan lint.

Suite browser SESSION_STABILITY memakai cookie SIMULATED yang ditandatangani kunci lama atau sudah kedaluwarsa; rute, pencarian tempat dan database bukan fixture. Pengujian berjalan dalam database scratch milik invokasi, pada lebar 390 dan 1280: pilih From/To dari katalog nyata, Find journeys, empat preferensi, pastikan pilihan OTP muncul, lalu aktifkan perjalanan. Setelah itu cookie lama dipasang kembali untuk membuktikan read/progress ditolak dan state perjalanan tidak berubah. ROUTING_STABILITY mengulang matriks jaringan terjadwal yang sudah ada. CP2 memeriksa kembali penolakan session expiry saat perjalanan aktif dan reload. Status eksekusi final dicatat di bukti invokasi, bukan diasumsikan dari rencana tes.

Percobaan inspeksi manual tab pengguna tertahan oleh kebijakan browser karena tab berada pada halaman error; tidak dilakukan bypass certificate maupun perubahan security browser. Bukti automated browser dan HTTP dibedakan dari manual test di tab pengguna. Jadwal tetap historis 2 Oktober 2026; akurasi GPS fisik, jadwal hari ini dan integrasi booking tidak berubah melalui perbaikan sesi ini.

Invokasi 6e41dc17-ff6d-459f-a7f2-b32a40f535ec mencatat SESSION_STABILITY (16 pencarian UI dengan cookie lama/expired), ROUTING_STABILITY (28 pencarian terjadwal) dan CP2 (termasuk expiry aktif) PASS. Runner tambahannya berhenti karena tes R4-F04 lama menolak sertifikat self-signed lokal. Kegagalan ini disimpan, bukan dihapus atau diklaim sebagai kelulusan keseluruhan. Perubahan ini hanya mengenai harness; browser pengguna dan server produksi tidak diberi pengecualian sertifikat. Container percobaan gagal dihentikan sesudah verifikasi label/identitas, sementara evidence dan storage dipertahankan.
